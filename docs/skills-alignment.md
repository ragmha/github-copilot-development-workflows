# GitHub Skills alignment

This repository is not an official GitHub Skills exercise. It is an original Copilot workflow exercise that follows the same learning shape: hands-on work in a real repository, guided by Issues, GitHub Actions, and Codespaces.

## Design principles

| Principle | How this repository applies it |
|---|---|
| Learn in a personal copy | Learners work in their own repository copy so commands, branches, Issues, and Pull Requests are real. |
| Keep the issue as the mission log | Each step asks learners to record intent, evidence, decisions, or reflection in the exercise issue. |
| Use GitHub Actions for feedback | Step workflows post guidance and CI runs tests, lint, typecheck, and content validation. |
| Prefer real GitHub surfaces | Codespaces, Issues, Pull Requests, Actions, and repository instructions are part of the exercise, not screenshots. |
| Make guidance helpful but not magical | The repo provides prompts and checks, while the learner still reads output, decides, and reviews. |

## What is intentionally different

This exercise focuses on GitHub Copilot development workflows instead of general GitHub feature onboarding. It uses the Skills pattern to teach agentic development habits:

- durable context in repository instructions,
- issue-driven planning,
- TDD evidence in the issue,
- safe delegation across agents,
- CI and security review before push,
- adoption notes tied to observable GitHub signals.
